# NoteforJun 설계 문서

작성일: 2026-09-11

## 1. 문제 정의

기존 메모 앱은 두 방향으로 실패한다.

노션이나 옵시디언은 규모가 큰 문제를 정리하기엔 좋지만 기능이 너무 많다. 무언가를 적기 전에 "이걸 어디에 어떤 형식으로 적을까"를 먼저 결정해야 한다. 반대로 투두메이트류는 단축키와 알림을 편의를 위해 넣었지만, 사용자는 그걸 익히다가 익숙해질 무렵 앱 자체를 안 쓰게 된다.

결국 살아남는 것은 윈도우 기본 스티키 노트다. 가볍고 단순하고, 생각이 떠오른 순간 바로 적을 수 있다. 규모가 큰 문제조차 스티키 노트로 처리하게 된다.

그러나 스티키 노트에는 네 가지 결핍이 있다.

1. 메모가 쌓이면 한눈에 무엇이 무엇인지 구분되지 않는다
2. 체크박스(할일)가 없다
3. 하이라이트(형광펜)가 없다
4. 글자 크기를 키울 방법이 없다

NoteforJun은 **스티키 노트를 베이스로 이 네 가지만 채우고, 그 외에는 아무것도 더하지 않는** 메모 앱이다.

## 2. 설계 원칙

### 2.1 자유도를 없애는 것이 기능이다

스티키 노트가 살아남은 이유는 기능이 적어서가 아니라 **결정할 것이 없어서**다. 색, 폰트, 글자 크기, 정렬 방식을 개발자가 미리 정해서 박아버리는 것 자체가 이 앱의 핵심 기능이다.

**설정 화면을 만들지 않는다.** 사용자가 조절할 수 있는 것은 메모 색(6가지 중 택1)과 창 크기·위치뿐이다.

### 2.2 기능 추가 판단 기준

> **이 앱에서만 통하는 것을 배워야 하는가?**

배워야 하면 넣지 않는다.

이 기준은 "모든 학습을 거부한다"는 뜻이 아니다. `Ctrl+B`(굵게)는 수십 년간 모든 프로그램에서 동일하게 동작해온 공용 지식이므로 사용자가 이미 알고 온다. 학습 비용이 0이다. 반면 이 앱만의 고유한 단축키나 문법은 배우는 비용이 발생하므로 배제한다.

### 2.3 발견되게 하되 강요하지 않는다

`# `을 치면 글자가 커지지만, 모르고 안 써도 손해가 없다. 드래그하면 서식 버튼이 뜨지만, 안 써도 메모는 작성된다. 모든 부가 기능은 **몰라도 앱을 쓸 수 있고, 우연히 발견하면 이득인** 구조여야 한다.

## 3. 범위

### 3.1 포함

- 메모 작성 및 자동 저장
- 제목 (상단바)
- 서식: 큰 글씨, 체크박스, 굵게, 기울임, 밑줄, 형광펜
- 메모 색상 6종
- 목록 창 + 검색
- 창 위치·크기 기억 및 복원
- 윈도우 시작 시 자동 실행

### 3.2 제외 (1차 버전에서 만들지 않음)

| 제외 항목 | 이유 |
|---|---|
| 알림 / 리마인더 | 익히다가 안 쓰게 되는 기능의 전형 |
| 이미지 붙여넣기 | 메모 크기가 들쭉날쭉해지고 저장 구조가 복잡해진다 |
| 텍스트 파일 내보내기 | 저장 파일이 이미 사람이 읽을 수 있는 형태로 폴더에 있다 |
| 클라우드 동기화 / 다중 기기 | 1인 사용 도구이며, 서버가 필요해지는 순간 성격이 달라진다 |
| 태그 / 폴더 / 정렬 옵션 | 분류를 강요하면 스티키 노트가 아니게 된다 |
| 휴지통 / 실행 취소된 삭제 복구 | 삭제 경로가 하나뿐이고 확인을 받으므로 불필요 |
| 다크 모드 / 테마 | 자유도 제거 원칙에 정면으로 위배 |
| 다단계 헤딩(`##`, `###`) | 메모에 문서 구조가 필요해지는 순간 다른 도구를 써야 한다 |

## 4. 화면 구성

창은 두 종류뿐이다.

### 4.1 메모 창 (여러 개)

```
┌──────────────────────────────┐
│ [+]  이번주 할일    [⋯] [×] │  ← 상단바 34px, 6색 중 하나
├──────────────────────────────┤
│                              │
│  장보기 먼저                 │  ← # 로 만든 큰 글씨 19px
│  ☑ 운동 30분                 │  ← 체크됨: 취소선 + 흐림
│  ☐ 세탁소 맡기기             │
│  금요일까지 끝내기           │  ← 형광펜
│                              │
└──────────────────────────────┘
     본문 배경: 아이보리 고정
```

**상단바 구성 요소 (좌 → 우)**

| 요소 | 동작 |
|---|---|
| `+` | 새 메모 창 생성 |
| 제목 입력칸 | 최대 20자. 비어 있으면 회색 "제목" 안내 문구 |
| 저장 표시 | 자동 저장이 끝나면 작은 `✓`가 잠깐 떴다가 스스로 사라진다 |
| `⋯` | 메뉴: **색 바꾸기**(6색 스와치), **모든 메모 보기** — 이 둘뿐 |
| `×` | 창 숨기기. 메모는 삭제되지 않고 목록에 남는다 |

**창 이동은 상단바 맨 위 가운데의 손잡이 선으로 한다.** 28px짜리 짧은 가로선이며, 상단바 글자색을 그대로 써서 6색 어디서나 어울린다. 상단바의 남는 빈 영역을 끌어도 창은 움직인다.

**크기 조절 영역도 직접 만든다.** 창 테두리를 끄면 OS가 주던 리사이즈 테두리도 함께 사라져서, 남은 판정 영역이 몇 px뿐이라 조준이 조금만 어긋나도 실패한다. 창 둘레에 보이지 않는 영역을 둘러 이를 대신한다 — 가장자리 8px, 모서리 20px.

모서리를 가장자리보다 넓게 잡는 이유는 사람이 창 크기를 바꿀 때 주로 모서리를 노리기 때문이다. 위쪽 영역은 창을 끄는 손잡이와 겹치지만 손잡이를 위층에 두어 끌기가 먼저 잡히게 한다 — 겹치는 구간에서 크기 조절 커서가 보이더라도, 그 자리를 비워 위쪽 가장자리로 크기를 못 바꾸게 만드는 것보다 낫다. 반대로 가장자리를 더 넓히면 안 된다. 본문 안쪽 여백이 12px이라, 가장자리 판정이 그만큼 넓어지면 글줄 맨 앞 글자를 클릭하려다 창 크기가 바뀐다. 그건 지금 문제보다 더 성가시다.

손잡이를 따로 둔 이유는 제목 때문이다. 제목 입력칸이 상단바 폭의 대부분을 차지하므로, 제목을 길게 쓰면 끌 수 있는 빈 공간이 사라진다. 빈 공간에만 의존하면 "제목을 쓸수록 창을 옮기기 어려워지는" 앱이 된다. 손잡이는 제목칸 위에 겹쳐 떠 있어 제목 폭을 전혀 뺏지 않으므로, 제목이 20자를 꽉 채워도 잡을 곳이 그대로 남는다.

**메모 창에서는 메모를 삭제할 수 없다.** 삭제 경로는 목록 창 하나뿐이다.

### 4.2 목록 창 (하나)

```
┌────────────────────────────────────┐
│  🔍 검색                    [+]    │
├────────────────────────────────────┤
│ ▌6월 일본여행 계획(오사카)         │  ← ▌색 띠
│ ▌ 숙소 예약 확인, 렌터카 비교…     │
├────────────────────────────────────┤
│ ▌외주 아이디어                     │
│ ▌ 사용자가 고를 게 없어야 한다…    │
├────────────────────────────────────┤
│ ▌(제목 없음 → 본문 첫 줄이 회색)   │
└────────────────────────────────────┘
```

- **폭은 제목 20자가 잘리지 않고 들어가도록** 잡는다. 기본 360×520이며 크기 조절은 가능하되 **최소 폭 360px**을 내려가지 않는다 (제목이 전부 보인다는 보증을 지키기 위해)
- 카드 = 왼쪽 색 띠 + 제목 + 본문 2줄 미리보기
- **정렬은 최근 수정순 고정.** 정렬 방식을 고르는 메뉴는 없다
- 검색: 입력하는 즉시 제목과 본문에서 걸러낸다. 대소문자를 구분하지 않는 단순 부분 일치이며, 초성 검색이나 정규식은 지원하지 않는다. 본문은 서식 태그를 제외한 순수 텍스트에서 찾는다
- 카드 클릭 → 해당 메모 창을 열거나, 이미 열려 있으면 앞으로 가져온다
- 카드 우클릭 → "메모 삭제". 확인 대화상자 1회 후 완전 삭제
- 우상단 `+` → 새 메모

## 5. 서식 규칙

이 목록이 전부다. 여기 없는 서식은 지원하지 않는다.

### 5.1 타이핑으로 만드는 서식

| 입력 | 결과 |
|---|---|
| `# ` (샵 + 띄어쓰기) | 그 줄이 19px 굵은 글씨가 되고 `#` 기호는 사라진다 |
| `- ` 또는 `[] ` (+ 띄어쓰기) | 체크박스로 변환된다 |

**헤딩은 한 단계뿐이다.** `##`, `###`는 동작하지 않는다.

**체크박스 동작**
- 클릭하면 체크/해제
- 체크되면 취소선이 그어지고 글자가 흐려진다(opacity 0.5)
- 체크해도 자동으로 위치가 바뀌지 않는다
- Enter를 누르면 다음 줄도 체크박스로 이어진다
- 빈 체크박스에서 Enter를 누르면 체크박스가 해제되고 일반 문단으로 돌아간다 (목록 탈출)

### 5.2 선택해서 적용하는 서식

텍스트를 드래그하면 선택 영역 위에 작은 팝업이 뜬다.

```
   ┌──────────────┐
   │  B  I  U  ✏  │
   └──────────────┘
```

| 버튼 | 단축키 | 효과 |
|---|---|---|
| `B` | `Ctrl+B` | 굵게 |
| `I` | `Ctrl+I` | 기울임 |
| `U` | `Ctrl+U` | 밑줄 |
| `✏` | 없음 | 노란 형광펜 (`#F7E27F` 고정) |

- 이미 서식이 적용된 부분을 선택하면 해당 버튼이 활성 상태로 표시되고, 누르면 해제된다
- **형광펜은 노란색 한 가지뿐이다.** 색 선택기는 없다
- 형광펜에 단축키를 두지 않는 이유: 프로그램마다 제각각이라 "이미 아는 단축키"가 존재하지 않는다. 드래그 팝업이 유일한 입구이며, 익숙한 `B I U` 옆에 놓아 자연스럽게 발견되게 한다
- **취소선은 별도로 제공하지 않는다.** 체크박스 체크 시 자동으로 적용되므로 역할이 겹친다

## 6. 색상

본문 배경은 **항상 아이보리 `#FBF8F2`** 로 고정하고, 색은 상단바에만 적용한다. 본문 배경을 고정하는 이유는 어떤 색을 고르더라도 글 읽는 경험이 동일해야 하고, 노란 배경 위의 노란 형광펜처럼 서식이 묻히는 일이 없어야 하기 때문이다.

| 이름 | 상단바 | 상단바 글자색 |
|---|---|---|
| 노랑 | `#E0B84D` | `#3D2F10` |
| 초록 | `#7FA86B` | `#FFFFFF` |
| 보라 | `#A98BC4` | `#FFFFFF` |
| 파랑 | `#6FA3BF` | `#FFFFFF` |
| 주황 | `#D98C6A` | `#FFFFFF` |
| 회색 | `#9A9A94` | `#FFFFFF` |

- 본문 글자색: `#2E2E2C`
- 형광펜: `#F7E27F`
- **새 메모는 항상 노랑으로 시작한다.** 직전 색을 기억하거나 자동 순환시키면 "왜 이 색이지?"를 생각하게 되는데, 그것이 바로 제거하려는 종류의 사고다

## 7. 타이포그래피

| 용도 | 폰트 | 크기 | 굵기 |
|---|---|---|---|
| 본문 | Pretendard | 14px | 400 |
| 큰 글씨 (`# `) | Pretendard | 19px | 700 |
| 제목 (상단바) | Pretendard | 13px | 600 |
| 목록 카드 제목 | Pretendard | 13px | 600 |
| 목록 카드 미리보기 | Pretendard | 12px | 400 |

- 본문 줄 간격 1.72
- **폰트는 앱에 포함한다.** 사용자 컴퓨터 환경과 무관하게 동일하게 보이도록 한다 (약 2~3MB)
- 폰트 선택 기능은 없다

Pretendard를 선택한 이유: 한글과 영문·숫자의 굵기와 높이가 맞아떨어져 섞어 써도 들쭉날쭉하지 않고, `0`과 `O`, `1`과 `l`의 구분이 명확하다. 메모에 계좌번호나 전화번호를 적는 일이 잦으므로 이 구분이 중요하다.

## 8. 제목 규칙

- **최대 20자** (입력 자체를 제한)
- 메모 창(기본 폭 300px)에서는 한글 기준 약 15자까지 보이고, 넘치면 `6월 일본여행 계…`처럼 말줄임 처리한다
- **목록 창은 20자가 전부 들어가는 폭으로 만든다.** 즉 메모 창에서 잘린 제목도 목록에서는 항상 온전히 보인다
- 제목은 필수가 아니다. 비워두면 목록 카드에 **본문 첫 줄이 회색으로** 표시된다

20자로 정한 근거: 제한의 목적은 공간에 맞추는 것이 아니라 **목록 창의 스캔 속도를 지키는 것**이다. 제목이 길어지면 목록에서도 잘리게 되고, 앞부분이 같은 긴 제목 둘이 목록에서 동일하게 보이는 문제가 생긴다. 20자는 "목록에서는 반드시 전부 보여준다"는 보증을 지킬 수 있는 최대치다.

## 9. 창 동작과 생명주기

| 항목 | 동작 |
|---|---|
| 기본 크기 | 300 × 300 |
| 최소 크기 | 220 × 160 |
| 위치·크기 | 창마다 기억하고 다음에 열 때 복원 |
| 크기 조절 | 창 둘레에 보이지 않는 판정 영역을 둔다. 가장자리 8px, 모서리 20px |
| `×` | 숨기기. 메모는 유지되고 목록에 남는다 |
| 삭제 | 목록 창에서만. 확인 1회 후 완전 삭제 |
| 자동 실행 | 윈도우 시작 시 실행 |
| 복원 | 종료 전 열려 있던 메모가 같은 자리, 같은 크기로 다시 뜬다 |

**새 메모를 만드는 경로 (세 가지)**

1. 작업표시줄 아이콘 **우클릭 → "새 메모"** (점프 목록)
2. 메모 창 또는 목록 창의 `+` 버튼
3. `Ctrl+Alt+N` (전역 단축키)

작업표시줄 아이콘을 **클릭**하면 목록 창이 열린다.

새 메모 창은 마지막으로 활성화된 창에서 오른쪽 아래로 24px씩 비껴서 뜬다. 열린 창이 없으면 화면 중앙에 뜬다. 화면 밖으로 벗어날 위치가 되면 다시 좌상단으로 돌아온다.

단축키는 `+` 버튼에 마우스를 올렸을 때 "새 메모 (Ctrl+Alt+N)" 툴팁으로만 노출한다. 외우라고 요구하지 않으며, 마우스를 쓰다가 눈에 들어오면 그때 쓰게 되는 방식이다.

시스템 트레이(시계 옆 알림 영역)는 쓰지 않는다. 아이콘이 숨김 처리되면 존재를 잊게 되기 때문이다. 작업표시줄 고정이 기본 동선이다.

## 10. 데이터 저장

### 10.1 위치와 형식

```
%APPDATA%\NoteforJun\notes\<uuid>.json
```

**메모 하나당 파일 하나.** 한 파일에 전부 담으면 그 파일이 손상될 때 모든 메모를 잃지만, 메모당 파일이면 최악의 경우에도 메모 하나만 잃는다. 또한 폴더를 열면 파일이 그냥 거기 있으므로 복사해두는 것이 곧 백업이 된다 — 내보내기 기능이 불필요한 이유다.

**파일 구조**

```json
{
  "id": "5f3c...",
  "title": "6월 일본여행 계획(오사카)",
  "content": "<p>...</p>",
  "color": "yellow",
  "window": { "x": 120, "y": 340, "width": 300, "height": 300, "visible": true },
  "createdAt": "2026-09-11T14:30:00Z",
  "updatedAt": "2026-09-11T15:02:11Z"
}
```

`content`는 Tiptap이 생성하는 HTML 문자열을 그대로 저장한다.

### 10.2 저장 시점과 안전성

- 타이핑이 멈추고 **500ms 후** 자동 저장 (디바운스)
- 창 이동·크기 조절이 끝난 시점에도 저장
- 창을 숨기거나 앱을 종료할 때 즉시 저장

저장이 끝나면 상단바에 작은 `✓`가 0.9초쯤 떴다가 스스로 사라진다. 아무 신호 없이 조용히 저장하면 사용자는 저장됐는지 알 수 없어 불안해지고, 그렇다고 "저장됨" 표시를 늘 띄워두면 잔소리가 된다. 나타났다 사라지는 편이 둘 다 피한다. 표시할 자리는 비어 있을 때도 늘 차지해 둔다 — 나타날 때마다 제목칸 폭이 들썩이면 글 쓰는 동안 눈에 거슬린다.

**원자적 쓰기**: `<uuid>.json.tmp`에 먼저 기록한 뒤 `<uuid>.json`으로 이름을 바꾼다. 이름 바꾸기는 성공하거나 아예 일어나지 않으므로, 저장 도중 전원이 꺼져도 반쯤 쓰이다 만 파일이 생기지 않는다.

## 11. 기술 구조

### 11.1 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 프레임워크 | **Tauri 2** | 메모 하나가 창 하나인 구조라 창 수만큼 메모리가 늘어난다. Tauri는 윈도우에 내장된 WebView2를 여러 창이 공유하므로 Electron 대비 메모리가 크게 낮다 |
| 화면 | **순수 HTML/CSS/JS** | 화면이 두 종류뿐이라 프레임워크가 필요 없다 |
| 편집기 | **Tiptap** (ProseMirror 기반) | 아래 설명 |

### 11.2 편집기에 라이브러리를 쓰는 이유

서식이 6종뿐이므로 `contenteditable`을 직접 제어하는 것도 가능하다. 그러나 **한글 입력** 때문에 그렇게 하지 않는다.

한글은 자음과 모음을 조합하는 동안 브라우저가 글자를 계속 고쳐 쓴다(IME 조합 상태). 이 중간 상태를 직접 다루면 글자가 씹히거나 커서가 튀는 버그가 발생하기 쉽고, 메모 앱에서 이는 치명적이다. Tiptap은 이 문제가 이미 검증된 코드이며 약 100KB로 부담이 없다.

**사용할 Tiptap 확장**: Document, Paragraph, Text, Heading(level 1만), TaskList, TaskItem, Bold, Italic, Underline, Highlight, History, 그리고 `# `과 `- `를 위한 입력 규칙(InputRule).

### 11.3 창 구조

- 메모 창: `note.html?id=<uuid>` — 창마다 같은 HTML을 열고 id로 구분
- 목록 창: `list.html` — 단 하나만 존재

### 11.4 Rust가 맡는 일

1. 메모 파일 읽기·쓰기·삭제 (원자적 쓰기 포함)
2. 창 생성·숨김·복원, 위치·크기 기록
3. 전역 단축키 `Ctrl+Alt+N` (`tauri-plugin-global-shortcut`)
4. 윈도우 시작 시 자동 실행 등록 (`tauri-plugin-autostart`)
5. 작업표시줄 점프 목록 등록

**점프 목록에 관한 판단**: 점프 목록은 윈도우 고유 기능이라 Tauri가 직접 지원하지 않을 수 있다. 구현을 시도하되 윈도우 API 연동이 막히면 **생략하고** 나머지 두 경로(`+` 버튼, `Ctrl+Alt+N`)로 대체한다. 이 경우 작업표시줄 아이콘 클릭 시 목록 창이 열리고, 거기 `+` 버튼으로 새 메모를 만든다.

### 11.5 Rust ↔ 화면 인터페이스

| 명령 | 입력 | 출력 |
|---|---|---|
| `list_notes` | — | 메모 요약 목록 (id, 제목, 본문 순수 텍스트, 색, 수정시각) |
| `load_note` | id | 메모 전체 |
| `save_note` | 메모 전체 | — |
| `create_note` | — | 새 id |
| `delete_note` | id | — |
| `open_note_window` | id | — |
| `hide_note_window` | id | — |
| `open_list_window` | — | — |

요약에 미리보기 문자열이 아니라 **본문 전체의 순수 텍스트**를 담는 이유는 검색이 본문 전체를 훑어야 하기 때문이다. 2줄 미리보기는 이 텍스트에서 화면 쪽이 잘라 쓴다. HTML에서 태그를 걷어내는 일은 Rust가 한 번만 한다.

메모를 삭제할 때는 열려 있는 창을 숨기는 것이 아니라 닫아야 하므로, 창 관리 쪽에 `close_note`를 별도로 둔다.

각 단위는 독립적으로 테스트 가능해야 한다. 파일 저장 로직은 창 관리 로직을 모르고, 창 관리 로직은 편집기 내부를 모른다.

## 12. 완성 판단 기준

"동작한다"가 아니라 아래를 전부 통과하면 완성이다.

### 12.1 서식

1. `# ` + 띄어쓰기로 큰 글씨가 되고, `#` 기호가 화면에 남지 않는다
2. `- `와 `[] `가 각각 체크박스로 변환된다
3. 체크박스 클릭 시 취소선과 흐림이 적용되고, 위치는 바뀌지 않는다
4. 체크박스에서 Enter를 누르면 다음 체크박스가 생기고, 빈 체크박스에서 Enter를 누르면 목록을 빠져나온다
5. 드래그 시 `B I U ✏` 팝업이 뜨고, 네 버튼이 각각 적용·해제된다
6. `Ctrl+B` / `Ctrl+I` / `Ctrl+U`가 동작한다
7. 이미 서식이 적용된 부분을 선택하면 해당 버튼이 활성 상태로 보인다

### 12.2 한글 입력

8. **한글을 조합하는 도중**(예: `ㅎ` → `하` → `한`) 서식이 깨지거나 커서가 튀지 않는다
9. 한글 조합 중 자동 저장이 발생해도 글자가 유실되지 않는다

### 12.3 저장과 복원

10. 메모를 쓰는 도중 앱을 강제 종료해도 **0.5초 이전까지 작성한 글이 남아 있다**
11. 저장 파일을 중간에 잘라내는 등으로 손상시켜도 **다른 메모는 정상적으로 열린다**
12. 재부팅 후 열려 있던 메모가 **같은 자리, 같은 크기**로 복원된다
13. `×`로 닫은 메모가 목록 창에 남아 있고, 클릭하면 다시 열린다

### 12.4 제목과 목록

14. 제목에 21번째 글자가 입력되지 않는다
15. 메모 창에서 잘린 제목이 목록 창에서는 전부 보인다
16. 제목이 빈 메모는 목록에서 본문 첫 줄이 회색으로 표시된다
17. 검색어를 입력하면 제목과 본문 양쪽에서 걸러진다

### 12.5 성능과 철학

18. 메모 20개를 띄웠을 때 메모리 사용량이 **250MB 아래**
19. 새 메모 창이 뜨기까지 **0.5초 이내**
20. **설정 화면이 없다.** 사용자가 조절할 수 있는 것은 메모 색 6가지와 창 크기·위치뿐이다
